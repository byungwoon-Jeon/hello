# Claude Code 주요 명령어

> 설치 버전과 회사의 관리 정책에 따라 일부 명령어가 없거나 동작이 다를 수 있다. 우선 `/help`와 `/status`로 확인한다. VS Code 확장과 터미널 CLI의 제공 UI도 다를 수 있다.

| 명령어 | 목적 | 추천 사용 상황 |
|---|---|---|
| `/help` | 사용 가능한 명령어 표시 | 처음 실행 |
| `/status` | 버전, 모델, 연결 상태 확인 | 사내 모델/게이트웨이 확인 |
| `/init` | 프로젝트 `CLAUDE.md` 초안 생성 | 프로젝트 최초 진입 |
| `/context` | 문맥 사용량 확인 | 대화가 길어질 때 |
| `/compact [지시사항]` | 대화를 요약·압축 | 같은 작업 장기 진행 |
| `/clear` | 대화 기록 비우고 새 작업 | 다른 업무로 전환 |
| `/resume` | 이전 세션 이어가기 | 중단했던 업무 복귀 |
| `/plan [작업]` | 코드 변경 전 계획 모드 | 운영 코드 영향 분석 |
| `/permissions` | 도구 허용/질문/차단 규칙 | 권한 관리 |
| `/rewind` | 대화·파일 수정 체크포인트로 복귀 | 잘못된 수정 |
| `/doctor` | 설치 및 환경 진단 | 확장 문제 해결 |
| `/review` | 변경 코드 검토 | 리뷰 필요할 때 |
| `/model` | 모델 선택/확인 | 회사 허용 모델 확인 |
| `/hooks` | Hooks 목록·설정 확인 | 자동 검증 도입 |
| `/mcp` | MCP 연결 확인 | 사내 승인 MCP 존재 시 |

## 실무 흐름 예시

### 1. 작업 시작

```text
/plan 영수증 추출 결과 필드를 추가해야 해.
관련 파일, 호출자, 반환 형식의 영향만 먼저 분석해.
코드는 수정하지 마.
```

### 2. 긴 대화 압축

```text
/compact 현재 작업의 요구사항, 수정된 함수, 기존 인터페이스,
확정된 설계 결정, 아직 실행하지 못한 테스트를 유지해.
```

### 3. 새 작업

```text
/clear
```

## 주의

- `/compact`는 압축된 요약이 모든 세부사항을 완벽히 보존한다는 보장이 없다. 장기 규칙은 `CLAUDE.md`와 작업 문서에 남긴다.
- `/rewind`는 Git 커밋·백업을 대체하지 않는다.
- `/model`의 'Sonnet/Opus' 표시가 사내에서 실제로 어떤 DeepSeek 모델을 호출하는지는 내부 모델 매핑에 따라 다르다.
- DeepSeek 모델이 도구 호출에 실패하면 명령어의 존재 여부와 모델/API 호환 문제를 분리해 진단한다.
