# 회귀 테스트 설계 및 검증

대상 변경 사항:

$ARGUMENTS

1. 먼저 현재 변경사항과 요구사항, 관련 테스트의 위치를 확인한다.
2. 다음 시나리오의 해당 여부를 평가한다.
   - 정상 입력과 정상 출력
   - 빈 값, null, 누락 필드, 잘못된 타입
   - 손상된 파일, OCR 실패, LLM 출력 파싱 오류
   - 타임아웃, 재시도, 중복 처리
   - DB 연결 실패, 저장 실패, 부분 처리
   - 기존 인터페이스 및 CSV/JSON 출력 호환성
3. 각 시나리오에 대해 목적, 테스트 입력, 기대 결과, 검증 방법을 정리한다.
4. 기존 테스트 프레임워크와 명령을 확인한다.
5. 테스트 코드 작성·실행으로 실제 파일이나 외부 시스템이 변경된다면 먼저 승인받는다.
6. 실행된 테스트와 제안만 한 테스트를 명확히 구분한다.

운영 DB, 실데이터 또는 외부 API를 호출하는 테스트는 승인 없이 실행하지 않는다.
테스트가 통과했다고 추측하지 않는다.
